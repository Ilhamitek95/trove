## Safety rules (never break)

- **Always ship live (owner instruction 2026-09-02):** every change is committed, pushed, deployed on Render, and verified live in the same turn — no local-only stops. Run the tests first; still pause for anything destructive (prod DB writes, unseen migrations).
- **`PAYOUT_ENC_KEY` (Render env) is irreplaceable** — if lost, all stored seller IBANs are unrecoverable. Never rotate or "clean up" this var.
- Copy guardrails are CI-enforced (`backend/test/copy-guardrails.test.js`): no carbon-neutral/greenwashing claims, no money-transmission phrases. Never fabricate reviews, ratings, or stats — live mode only shows real data.
- Prod DB never reseeds once users exist; `npm run seed` is for local dev only. **Live demo data was cleared on 2026-09-22** (owner: one shop with one piece + one service provider remain) with `backend/scripts/purge-demo.js` (`npm run purge-demo -- --keep-shop=<slug> --keep-product=<id> --keep-provider=<slug>`; dry run by default, `--yes` backs up via VACUUM INTO then removes; `test/purge.test.js`). Because of that, boot-time demo providers are now opt-in (`DEMO_PROVIDERS=1`, never set on Render) — the local seed still creates them.
- The user's email is the ONLY admin on prod (bootstrapped from `ADMIN_EMAIL` env). Demo accounts on prod are re-passworded every boot from `DEMO_PASSWORD` env (local dev stays `demo1234`).
- **Admin second sign-in step (2026-10-02, `src/admin-2fa.js`):** after the password or Google, an admin gets a 6-digit code by email (10 min, 5 tries; logged to the server console when `RESEND_API_KEY` is not set) and finishes at `POST /api/auth/admin-code`; 'Trust this browser' skips it for 30 days (`admin_devices`, hash only; a password change/reset forgets them). Admin sessions and shop view last `ADMIN_SESSION_HOURS` (default 12), enforced server-side by `guard` in app.js. **Owner lock-out recovery: set `ADMIN_2FA=off` in Render → Environment and redeploy, sign in with the password alone, then delete the variable.** Live QA scripts that sign in as the admin must now complete the code step. Tests: `loginAs` completes it via `_lastCode()` (test env only).
- **Maker identity before payment (2026-10-02, `src/identity.js`, migration `022-C`):** a typed licence number never skips the Emirates ID step — only an admin-verified licence does. Settlement pays a maker only when identity is established: verified licence, or Emirates ID photos + details + home address that the admin ticked 'Mark ID checked' (Admin → Shops) and that have not expired (`shops.verification_method` = trade_licence / emirates_id, room for uae_pass later). Payout account-holder names that don't match the maker or shop are flagged in Shops + the settlement preview. Daily 02:00 sweep emails makers 30 days before and at ID expiry. ## Arabic edition (owner 2026-10-02, branch feat/arabic)

- **Every public address has an Arabic twin under `/ar`** (`/ar`, `/ar/shop/<cat>`, `/ar/pieces/<id>-<slug>`, `/ar/makers/<slug>`, `/ar/services[/<slug>]`, info + legal pages, `/ar/apply`, `/ar/login`, `/ar/account`, `/ar/sell`, `/ar/provider`); slugs stay Latin. `/admin` stays English (no twin, `/ar/admin` = 404). Modern Standard Arabic; "Trove" stays Latin; Western digits; no italics.
- **`src/i18n.js` middleware** (mounted after the session in app.js) strips `/ar`, sets `req.lang`, and finishes EVERY HTML response (`finishPage`): translates the page's static text with its dictionaries (text nodes, placeholder/title/aria-label/alt, `data-i18n` blocks; never inside `<script>`/`<style>`/`translate="no"`), sets `<html lang="ar" dir="rtl">`, injects `window.TROVE_I18N` for the page script + `docs/rtl.css`, rewrites local links to `/ar`, and writes canonical + hreflang en/ar/x-default from the English canonical (pages without a canonical — private ones — get none). Local redirects on an Arabic request keep `/ar`. On `/api` it sets `req.lang` from `?lang=ar` or `X-Trove-Lang` (docs/api.js sends both). Sitemap lists both languages with `xhtml:link` alternates; robots disallows the `/ar` private twins.
- **Remembered choice:** an `/ar` page sets cookie `trove_lang=ar` and `users.lang` (signed in); an English localizable page with that cookie (or a signed-in account set to Arabic) 302s to its twin (`Vary: Cookie`); the English switch is `?hl=en`, which resets both. The header switch is `<a data-lang-switch>` (desktop `.langsw` + mobile menu `.mn-lang`, identical in trove.html and trove-services.html — header-sync); finishPage fills its href per page; `troveSwitchLang()` in api.js handles clicks (SPA paths).
- **Dictionaries:** `docs/i18n/ar/<bundle>.json`, keyed by the English text (gettext style); `docs/i18n/en/` mirrors the keys (`node scripts/i18n-sync.js` regenerates it; plural entries are `{one, other}` in English, CLDR forms zero/one/two/few/many/other in Arabic). A page names its bundles in `<meta name="trove-i18n" content="storefront,content">`; `common` is always included. Browser helpers in docs/api.js: `_t('English {x}', {x})`, `_tn(n, '{n} piece', '{n} pieces')`, `troveMoney`/`troveIso` (LRI…PDI isolate so 'AED 120' never scrambles; dictionary values get it automatically), `troveDate`, `troveUrl('/x')` (→ `/ar/x` on Arabic pages), `trovePath()` (strips `/ar`); history.pushState/replaceState and new `<a href>`s keep the prefix automatically. Server: `i18n.t(lang, '…', vars, bundles)`, `i18n.tn`, `i18n.money`, `i18n.date`. **Keys must be literal strings** — `test/i18n-dictionaries.test.js` scans every page, provider-panel.js, api.js, site-chrome.js and backend/src for `_t(`/`_tn(`/`i18n.t(`/`T(` and fails on a missing key, a key mismatch between en/ and ar/, or lost `{placeholders}`. When you add or change UI copy: add the English key + Arabic to the right bundle and run the sync script.
- **Fonts:** `docs/rtl.css` adds Arabic glyphs INTO the brand families by unicode-range (`'Quicksand'` → IBM Plex Sans Arabic, `'Cormorant'` → Noto Naskh Arabic, from fonts.gstatic.com), so existing font-family rules just work and the files load only on Arabic pages. It also zeroes letter-spacing (breaks joined script), loosens heading line-height and mirrors the shared header/menu/footer; page-specific mirroring lives in each page's `<style>` under `[dir="rtl"]`.
- **What people create is machine-translated (`src/translate.js`, migration `023-arabic`):** pieces (name, description, option names/values, extras, personalisation prompt), shop story + area, provider bio + area, services (title, description, duration), admin site-content overrides, published reviews. Proper names (shops, makers, providers, buyers) are never translated. Table `translations` (entity, entity_id, field, lang) stores the Arabic with the SHA-256 of its English: it shows ONLY while that English is unchanged (stale → English shown + re-queued). Saves call `translate.queue()` (seller/admin/provider routes, reviews.js) and never wait; a background worker drains `translation_queue`, plus a boot + hourly sweep (`translate.start()` in server.js). - Product options & variants (`src/options.js`): `products.options` = `[{name,values[]}]` (max 3 groups × 20 values); every combination is a variant in `products.variants` = `[{key,options,stock,priceCents}]` with **its own stock and optional price**; the buyer's pick is snapshotted on `order_items.options`. **The server rebuilds the whole grid on every seller save** (merging submitted stock/price by key), so a combination missing from the grid simply doesn't exist and can't be sold. `products.stock` is kept equal to the sum of the grid — everything else in the app keeps reading that one number. Key format is `Colour:Sand|Size:Large`, in group order. Nothing is preselected on the PDP; unavailable values are struck through relative to the other picks; checkout resolves price and stock from the variant, counts quantities across the whole basket, and 409s per combination.
- Priced extras (`src/extras.js`): `products.extras` = `[{name,priceCents}]` (max 6; price 0 = free extra), edited in the drawer's Paid-extras rows; always optional for the buyer — never required, never preselected. The ticked ones are snapshotted on `order_items.extras` (name + price at purchase) and their cost is **folded into the line's `price_cents`**, so settlement, returns and VAT keep reading the one number they always have — a refund of a gift-wrapped piece automatically includes the wrap. The server prices extras from the product row; the client only ever names them (`test/extras.test.js` mutation-tests this). A basket line's identity includes its extras, so a wrapped and an unwrapped mug are separate lines; a retired extra drops the saved line on restore, like a retired option value.

OTO (tryoto.com) is a multi-courier gateway: one Trove account + wallet pays every delivery, each maker is an OTO pickup location (`trove-shop-<id>`, created/updated on demand from `shops.pickup_address`/`pickup_phone` + owner name/email). Flow: payment → `createOrder` (orderId `<public_id>-<shipment id>` = `delivery_ref`, pickupLocationCode, customer from shipping snapshot + `orders.phone`, items sku `OI-<order_item id>`, pre-paid AED, NO buyer email) → maker taps Packed → `checkOTODeliveryFee` + `createShipment` with the CHEAPEST door-to-door option that has a courier pickup (lockers/PUDO/drop-off-only excluded; `OTO_DELIVERY_OPTION_ID` pins one, `OTO_SERVICE_TYPE` prefers e.g. sameDay) → carrier renamed to the chosen courier → label = redirect to OTO's hosted `printAWBURL` → webhooks `POST /api/delivery/oto-webhook?t=status|error` (signature = base64 HMAC-SHA256 of `orderId:status:timestamp` with `OTO_WEBHOOK_SECRET`, also sent as the authorization key; dedupe in webhook_events; shipmentError clears ready_at so re-marking packed retries). Webhooks are registered by server.js `otoBoot()` at every boot (idempotent, needs OTO_WEBHOOK_SECRET + https CLIENT_URL); boot log prints plan + wallet. Returns = `createReturnShipment` on the forward orderId (only after OTO has it delivered) with the returned skus → `<ref>-R1`, back to the maker's location.
