# Trove (trove-vu4z.onrender.com)

Curated multi-vendor marketplace, Dubai + Abu Dhabi only, currency AED (stored as integer **fils**). Owner is non-technical: do all code work yourself, give click-by-click steps for dashboards, never paste secrets into chat. Separate project from Daily Comps.

## Business model (locked — don't drift)

- Consignment "Rail A": Trove is merchant of record; commission **40%** (makers keep 60%), **no buyer service fee** (owner: "no hidden costs", 2026-08-02), delivery **AED 30 charged on orders of AED 200 and below** (free above; exactly AED 200 pays — `deliveryFor` uses `>`). All money rules live in `backend/src/fees.js` (env-overridable). Division of labour (owner, 2026-08-02): Trove arranges + pays the courier (booked through OTO since 2026-09-21) and does all marketing + photography (funded by the 40%); **makers pack sold pieces in their own packaging** and hand them to the courier. **Fortnightly settlement (owner 2026-09-30: 'bi-weekly shop payments with 15 days return policy')**: every other Tuesday from `fees.SETTLEMENT_ANCHOR_DATE` (2026-10-06, `SETTLEMENT_INTERVAL_DAYS` 14; the Tuesday cron skips off weeks via `settlement.isRunDate`), and a credit is payable only once the buyer's 15-day window (`fees.RETURN_WINDOW_DAYS`) has closed with no return in flight; bank CSV export is the ONLY place IBANs decrypt.
- Rail B (Stripe Connect graduation) exists behind `RAIL_B_ENABLED=0` — off by default.
- Seller agreement current version is **v4** (40% margin, fortnightly payouts, 15-day returns; makers on an older version see a non-blocking re-accept banner → `POST /api/seller/agreement`). v1–v3 md files stay untouched as the signed record — on any terms change add a new md and bump `AGREEMENT_VERSION` in `src/config.js` (onboarding tests pin the literal).
- Service area is Dubai + Abu Dhabi only, enforced server-side (`backend/src/service-area.js`).
- **Services marketplace (2026-09):** providers enrol at `/become-a-provider` (admin approves in /admin → Providers), list in-person services (`/services`, taxonomy in `backend/src/service-taxonomy.js` — 12 categories, two audiences), and manage bookings at `/provider`. Money model (2026-09-08): **the AED 30/month provider fee is FREE DURING LAUNCH** (owner 2026-09-30; `fees.PROVIDER_SUB_FEE_CENTS` kept for later, 30 days notice promised; `sub_started_at` is data only) and a booking is paid one of two ways, chosen by the customer and snapshotted on the row: `direct` (settled customer↔provider, bank transfer/cash — Trove takes nothing) or `trove` (card flow LIVE 2026-09-30: provider confirms with date + final price → PaymentIntent → emailed pay link `/services/pay/…` → webhook `payment_intent.succeeded` metadata.kind=service_booking marks paid + writes `provider_credits`; server gate = Stripe secret configured; provider payouts are MANUAL bank transfers from Serein Consultancy on Trove's behalf (owner 2026-09-30; `PROVIDER_PAYER_NAME`): providers add bank details under Payouts in the dashboard (`provider_payout_details`, migration 018, IBAN encrypted like shops, masked in every response, optional server-side copy from their shop) → admin Providers → Provider payouts → Download bank transfer file (the only place a provider IBAN decrypts; reference `TRV-SVC-<provider id>-<yyyymmdd>`) → Mark paid stamps paid_at + reference + payer and emails the provider (`src/provider-payouts.js`, `test/provider-payouts.test.js`); Trove keeps `fees.SERVICE_COMMISSION_PERCENT` = 10, `commission_cents`/`provider_net_cents` snapshotted). Framing for `trove` bookings mirrors products: Trove is the customer's contracting party and engages the provider as independent contractor — never payment-aggregation language (copy guardrails). **Terms:** `backend/legal/provider-agreement-v2.md` (v2 2026-09-30: free during launch, final price on confirm) (accepted at apply / enable-services → `agreement_version`) and `services-terms-v2.md` (accepted per booking → `terms_version`), versions in `config.js`, served by `/api/legal/:doc`, pages `/provider-agreement` + `/services-terms`; both say the provider, not Trove, is responsible for the service. Drafted by Claude — owner to have a UAE lawyer review before launch. Contact privacy mirrors products: providers never see the customer email, and the phone is released only on confirm (`test/services.test.js` pins both). Tables `service_providers`/`services`/`service_bookings` are baseline CREATEs in db.js (no migration). **Demo providers** (`backend/src/demo-providers.js`, 6 approved + 1 pending, Mara of Kiln & Clay doubles as one) are created idempotently at every boot AND by the seed — keyed on slug, so an edited demo profile is never overwritten; their emails sit in server.js `DEMO_EMAILS` for the prod password rotation. Public browsing: `/services` directory + `/services/<slug>` provider page (`GET /api/services/providers[/:slug]`, approved + live only, never contact details). **One account, shop + services (2026-09-08):** `docs/provider-panel.js` is THE services dashboard (status/subscription/agreement card, listings editor, bookings inbox) — mounted by `/provider` AND by the seller dashboard's Services tab; an approved maker switches services on via `POST /api/seller/enable-services` (profile built from the shop, live immediately — owner's decision; pending shop → pending practice); `/apply` carries an 'I also offer services' toggle that fires `/api/services/apply` on the same session; shop ↔ provider pages cross-link (`shop.provider` / `provider.shop` in the public APIs, approved+live only; storefront addresses `/makers/<slug>`, `/pieces/<id>-<slug>`); admin has a Members tab (one row per account, both sides, approvals inline).
- **Stripe is LIVE in production (real money)** since late Sept 2026 — never test payments on live. Buyer Terms of Sale + Privacy Policy (`backend/legal/buyer-terms-v2.md` — v2 2026-09-30 changed only the delivery clause to per-piece estimates; `privacy-v1.md`, pages /terms /privacy) are Claude drafts awaiting UAE lawyer review. ## Safety rules (never break)

- **Always ship live (owner instruction 2026-09-02):** every change is committed, pushed, deployed on Render, and verified live in the same turn — no local-only stops. Run the tests first; still pause for anything destructive (prod DB writes, unseen migrations).
- **`PAYOUT_ENC_KEY` (Render env) is irreplaceable** — if lost, all stored seller IBANs are unrecoverable. Never rotate or "clean up" this var.
- Copy guardrails are CI-enforced (`backend/test/copy-guardrails.test.js`): no carbon-neutral/greenwashing claims, no money-transmission phrases. Never fabricate reviews, ratings, or stats — live mode only shows real data.
- Prod DB never reseeds once users exist; `npm run seed` is for local dev only. **Live demo data was cleared on 2026-09-22** (owner: one shop with one piece + one service provider remain) with `backend/scripts/purge-demo.js` (`npm run purge-demo -- --keep-shop=<slug> --keep-product=<id> --keep-provider=<slug>`; dry run by default, `--yes` backs up via VACUUM INTO then removes; `test/purge.test.js`). Because of that, boot-time demo providers are now opt-in (`DEMO_PROVIDERS=1`, never set on Render) — the local seed still creates them.
- The user's email is the ONLY admin on prod (bootstrapped from `ADMIN_EMAIL` env). Demo accounts on prod are re-passworded every boot from `DEMO_PASSWORD` env (local dev stays `demo1234`).

- Run locally: `cd backend && npm install && npm run seed && npm run dev` → http://localhost:4242 (Express also serves `docs/` statically — single origin).
- **Never round-trip repo files through PowerShell `Get-Content`/`Set-Content`** — it mojibakes UTF-8 (corrupted a route file once). Use the Edit/Write tools.
- Git commit messages containing double-quotes fail under PowerShell 5.1 quoting — avoid `"` in messages.
- Frontend is 4 self-contained HTML pages in `docs/` (trove.html storefront, trove-login, trove-account, trove-seller, plus trove-admin, trove-apply); shared client is `docs/api.js`. After editing inline JS, syntax-check with `node --check` via a temp extract.

- **Clean addresses + server rendering (2026-09-30, `backend/src/seo.js`):** every public view has its own URL — `/`, `/shop`, `/shop/<category-slug>` (`trove-collection` = house line), `/pieces/<id>-<slug>`, `/makers/<shop-slug>`, `/sell-on-trove`, `/services`, `/services/<slug>` — served with its own title/description/canonical/OG/Twitter tags, JSON-LD (Product+Offer with Trove as seller and the maker as brand/manufacturer, BreadcrumbList, ItemList, LocalBusiness+OfferCatalog for providers) and the view switched on with its key text written into the markup (one `<h1>` per page: inactive views' titles carry `data-vh` and are `<h2>` until shown). The storefront uses `history.pushState` + a `popstate` handler and intercepts plain clicks on real `<a href>`s; `slugify()` exists three times (seo.js, trove.html, trove-services.html) and `test/seo.test.js` pins them equal. Old `/?p=`, `/?shop=`, `/?view=` 301 to the new URLs; wrong slugs 301; unknown/delisted/unapproved = real 404 + noindex; capitals and trailing slashes on public paths 301 to lowercase. Sitemap `<lastmod>` = `updated_at` (stamped by SQLite triggers on shops/products/service_providers/services). Default share image `docs/img/og-default.jpg`; `favicon.ico` + `site.webmanifest` in docs/. The header wordmark is typed text (no `<img>`) until the official artwork lands.

Layering rule: a positioned `.grad` div must never cover the image — give the `img` `position:absolute;inset:0;z-index:1`.

- Browser QA gotcha: native `confirm()`/`prompt()` dialogs freeze automation — override (`window.confirm=()=>true`) before clicking buttons that trigger them.
- AI tag-writer (`backend/src/ai.js`, claude-haiku-4-5 via `AI_TAGS_MODEL`) needs `ANTHROPIC_API_KEY` (set on Render); endpoints 503 without it and the UI hides the button — degrade, don't error.
- Returns are UNIT-LEVEL (migrations 011 + 016, policy 2026-09-30): a request names order items AND how many units (`return_request_items.qty`); a unit sits in max one non-declined request. **15-day window** from delivery (orders placed before 2026-09-30 keep 30 days via `orders.return_days`). Reasons: changed-mind / damaged (faulty or damaged) / wrong-item / not-as-described; the AED 30 collection fee applies ONLY to changed-mind on orders ≤ AED 200 (admin can override on approval, `fee_override`) and is charged PER RETURN REQUEST (owner 2026-09-30 — the buyer form says 'send them back together … charged once'); **the original delivery fee is refunded when the whole order comes back for a fault** (owner 2026-09-30, migration 019: the fault request that, with the order's approved/collected/refunded requests, covers every unit, when all of them are fault reasons — stamped at approval as `delivery_refund_cents`, added to `refund_cents`, so the card refund + VAT reversal include it and maker credits never do; at most once per order; admin override `refundDelivery` → `delivery_override`; charging the fee on a fault claim drops it unless explicitly refunded; `test/return-delivery-refund.test.js`); personalised pieces only for the three fault reasons. Flow: requested → approved (books the courier collection, `return_collections`) → collected (OTO `reversePickedUp` / Quiqup-mock webhook / `POST /api/delivery/mock/collect-return`) → refunded (card refund, credit reversal, VAT reversal + credit note `CN-<order>-R<id>`); admin `refund-now` for exceptions. NO restock (owner 2026-07-30). Order stamps `refunded_at` only when every unit is refunded; unswept credits shrink in place, swept ones debit, closing exactly on the shop's last unit. Seller Revenue · 30d is net of refunds (`summary` on `/api/seller/orders`).
- Transactional email: `backend/src/email.js` (Resend HTTP API). Gated on `RESEND_API_KEY` + `EMAIL_FROM` (domain must be verified in Resend) — without the key every send logs "email skipped" and resolves, so local/tests need no setup. Always fire-and-forget with `.catch` — an email failure must never fail the request.
- Product photos: `products.images` (JSON array of `/uploads/products` URLs, max 4, first = cover). Client sends the FULL array each save (data URLs for new, `/uploads` URLs for kept); server deletes dropped files. Storefront falls back to motif tiles when empty (`pImg(p)` in trove.html).
- Product options & variants (`src/options.js`): `products.options` = `[{name,values[]}]` (max 3 groups × 20 values); every combination is a variant in `products.variants` = `[{key,options,stock,priceCents}]` with **its own stock and optional price**; the buyer's pick is snapshotted on `order_items.options`. **The server rebuilds the whole grid on every seller save** (merging submitted stock/price by key), so a combination missing from the grid simply doesn't exist and can't be sold. `products.stock` is kept equal to the sum of the grid — everything else in the app keeps reading that one number. Key format is `Colour:Sand|Size:Large`, in group order. Nothing is preselected on the PDP; unavailable values are struck through relative to the other picks; checkout resolves price and stock from the variant, counts quantities across the whole basket, and 409s per combination.
- Priced extras (`src/extras.js`): `products.extras` = `[{name,priceCents}]` (max 6; price 0 = free extra), edited in the drawer's Paid-extras rows; always optional for the buyer — never required, never preselected. The ticked ones are snapshotted on `order_items.extras` (name + price at purchase) and their cost is **folded into the line's `price_cents`**, so settlement, returns and VAT keep reading the one number they always have — a refund of a gift-wrapped piece automatically includes the wrap. The server prices extras from the product row; the client only ever names them (`test/extras.test.js` mutation-tests this). A basket line's identity includes its extras, so a wrapped and an unwrapped mug are separate lines; a retired extra drops the saved line on restore, like a retired option value.
- **OTO delivery (2026-09-21, `src/delivery/oto-live.js`) — the live courier path.** Owner switched from Quiqup because Quiqup could not collect from multiple addresses. OTO (tryoto.com) is a multi-courier gateway: one Trove account + wallet pays every delivery, each maker is an OTO pickup location (`trove-shop-<id>`, created/updated on demand from `shops.pickup_address`/`pickup_phone` + owner name/email). Live when `OTO_REFRESH_TOKEN` is set (OTO dashboard → Settings → API Integrations → Connect; takes precedence over Quiqup; `/api/health` shows `delivery: oto|quiqup|mock`). Flow: payment → `createOrder` (orderId `<public_id>-<shipment id>` = `delivery_ref`, pickupLocationCode, customer from shipping snapshot + `orders.phone`, items sku `OI-<order_item id>`, pre-paid AED, NO buyer email) → maker taps Packed → `checkOTODeliveryFee` + `createShipment` with the CHEAPEST door-to-door option that has a courier pickup (lockers/PUDO/drop-off-only excluded; `OTO_DELIVERY_OPTION_ID` pins one, `OTO_SERVICE_TYPE` prefers e.g. sameDay) → carrier renamed to the chosen courier → label = redirect to OTO's hosted `printAWBURL` → webhooks `POST /api/delivery/oto-webhook?t=status|error` (signature = base64 HMAC-SHA256 of `orderId:status:timestamp` with `OTO_WEBHOOK_SECRET`, also sent as the authorization key; dedupe in webhook_events; shipmentError clears ready_at so re-marking packed retries). Webhooks are registered by server.js `otoBoot()` at every boot (idempotent, needs OTO_WEBHOOK_SECRET + https CLIENT_URL); boot log prints plan + wallet. Returns = `createReturnShipment` on the forward orderId (only after OTO has it delivered) with the returned skus → `<ref>-R1`, back to the maker's location. OTO bills from a PREPAID wallet (OTO1006 = credit not enough). Free plan covers every endpoint used. `test/oto.test.js` runs against a fake OTO server. Docs: Postman collection behind apis.tryoto.com (sandbox https://staging-api.tryoto.com).
